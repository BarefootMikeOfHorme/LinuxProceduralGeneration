REAL PAIN POINTS THIS TASK MUST RELIEVE

  1. No verification discipline. There is no conftest.py. The full pytest run is
     very slow (test_batch_processing.py alone takes 5 minutes), so nobody can
     tell at a glance whether a change is safe. This is the top problem.

  2. A recurring bug class just got fixed and is currently UNGUARDED: modules
     inside vaultmind_forge/ did absolute top-level imports of sibling
     subpackages (`from forge_batch import X` instead of `from ..forge_batch
     import X`). Tests inserted `vaultmind_forge/` onto sys.path, which made
     the breakage invisible. It is fixed in the working tree but nothing
     prevents regression. Note the related residue: tests still pollute
     sys.path, so a module can be loaded under two identities, which already
     risks two instances of the `get_native_bridge()` singleton in
     forge_bots/native_bridge.py.

  3. Polyglot verification is fragmented. Rust (2 crates), Python, C++, and
     JSON Schema contracts each have their own check, and all are easy to
     forget. There is no single documented entrypoint.

  4. Dependency and version drift across a very diverse set — Python, Rust,
     C++, plus optional build123d/OpenSCAD/FreeCAD/Blender/FFmpeg/Docker.
     Config sprawl is itself a hazard: build/, dist/, target/, output/,
     outputs/, logs/, uploads/ and .venv312/ all need ignoring.

  5. quality_guardian.py has ~25 confirmed defects found by review and NOT yet
     fixed. Highest value first: it reports `overall_quality` and
     `before_quality` from `confidence` (a different quantity) so the report
     and all trend analytics are wrong; `issues_found` and `metrics` are always
     empty; a `TypeError` crash when `auto_fix_enabled=False`; metric
     computation failure is reported as "quality 0.0" -> REJECT; and image
     metric failure returns defaults that read as perfect. A reviewer noted the
     module's 8 "passing" tests assert almost nothing and are print-and-return
     scripts. A skill that generates real table-driven tests for pure decision
     functions would be genuinely useful here.

  6. Future: an install-plan/wizard workflow over the LPG-L1 tier model. The
     inert contracts already exist under LPGL1/L1/schemas/ (lifecycle-stage,
     scan-choice, install-task, install-plan, surface-binding) with 53 passing
     contract tests in vaultmind_forge/tests/test_lpg_l1_contracts.py.
